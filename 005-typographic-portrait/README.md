# 审美分享-05：故障艺术 × 文字肖像 × 后网络艺术

> 原帖：<https://x.com/Formulasearch> ｜ 2026-08

## 适用于

想让一张普通人像带上信息噪音感、又不想只是套个滤镜的时候。适合做头像、封面、活动主视觉，或者任何需要「人被文字淹没」这个隐喻的画面。

## 原帖观点

pixel sorting、typographic portrait、post-internet art 这一挂视觉的共同点是：**图像不再是图像，而是数据的一种显示方式**。

具体到文字肖像这一种，看起来像是「照片上撒了一堆字」，但真正让它成立的是四条规则：

1. **动态模糊**把人物从「一张照片」变成「一段运动的残留」，五官被抹掉，只剩轮廓；
2. **文字密度跟着主体走** —— 主体上最密，而且轮廓（明暗交界处）最密，字是从人形边缘「溢出」到背景里的；
3. **明暗反转配色** —— 暗部用浅色字、亮部用深色字，所以字永远读得出来，又不脱离照片；
4. **一部分文字是失焦的** —— 让文字和人物共享同一个镜头景深，看起来是「一张照片」而不是「照片上贴字」。

第 4 条最容易漏，但它是「合成感」和「摄影感」的分界线。

## 拿走即用

本期类型：**代码模板 + 可嵌入引擎**

### 1. 当工具用

打开 [template/index.html](template/index.html)（双击即可，零依赖零构建），拖入一张照片，调参数，导出 PNG。

- 拖拽 / `Ctrl+V` 粘贴 / 点「上传图片」都能进图
- 点画布 = 换一批随机排布
- 勾「闪烁」得到动态版：文字随机出现与消失

### 2. 嵌进自己的项目

把 [`typo-portrait.js`](template/typo-portrait.js) 拷进项目（单文件，约 15KB，无依赖）：

```html
<canvas id="portrait"></canvas>

<script src="typo-portrait.js"></script>
<script>
  const p = TypoPortrait.create(document.getElementById('portrait'), {
    words: ['Formulasearch', 'Prompt', 'Design'],
    cling: 0.82,
    color: true,
    motion: 'glitch',
  });
  p.setImage('photo.jpg').then(() => p.play());
</script>
```

工具里的「导出代码」按钮会把你**当前调好的全部参数**写进 HTML / React / JSON 三种片段，复制即用。

### API

| 方法 | 说明 |
|---|---|
| `TypoPortrait.create(canvas, options)` | 创建实例 |
| `setImage(src)` | 接受 URL 字符串、`File`/`Blob`、`<img>`、`<canvas>`，返回 Promise |
| `setOptions(patch)` | 局部改参数，内部自动判断要不要重算基底 |
| `play()` / `pause()` | 动效播放控制 |
| `reseed()` | 换一批文字排布 |
| `toDataURL()` | 导出图片 |
| `destroy()` | 停止动画并释放 |

主要参数见 `TypoPortrait.DEFAULTS`，每项都有注释。

## 复刻笔记

### 动态模糊：别用高斯，别在 sRGB 里平均

第一版用「错位叠画 + 高斯权重」，效果发闷、拖影是断的。查了 Photoshop 的做法后重写，两个关键点：

**一是核函数应该是盒式（box）而不是高斯。** Motion Blur 模拟的是相机快门在曝光时间内的**均匀积分**，所以沿运动方向的权重必须等权。高斯权重会让拖影两端渐隐，看起来像"重影叠加"而不是"一道干净的拖痕"。标准实现用滑动求和（窗口右移时加一个进入的像素、减一个离开的像素），每像素 O(1)，模糊长度再大也不变慢。

**二是必须在线性光空间里做平均。** 照片以 sRGB 伽马编码存储，直接对像素值取平均在物理上是错的 —— 亮部占据的数值空间被压缩，结果整体偏暗发闷。正确做法是先解码到线性光、在那里平均、再编码回去。这一条对画面的改善比任何调参都大，尤其是「深色主体 + 浅色背景」这种典型人像构图，人物边缘的拖影会从一团脏灰变成通透的浅色。

任意角度的做法是把图旋到「模糊方向 = 水平」，按行做，再转回来。0°/90°/180°/270° 时旋转无损，也就是最常用的几档没有任何重采样损失。

### 性能：两个坑

**逐字设 `ctx.filter` 会把帧率打到个位数。** 失焦文字最初是给每次 `fillText` 单独套一层 canvas blur，几百次滤镜操作直接卡死（实测 1 fps）。改成先全部画进离屏画布、最后整体模糊一次，降到 1～2ms/帧。

**只沿模糊轴降采样。** 盒式模糊会抹掉该方向上高于 `1/len` 的所有频率，所以按 `len/8` 的间距取样完全够用；而垂直于模糊方向的细节一点不动，画质无损。长模糊因此快 3～5 倍（423ms → 80～180ms）。

### 「往暗处聚」是错的，应该是「往偏离背景处聚」

第一版把规则写成「越暗的地方文字越密」，用浅底深色人物测试一切正常。换上一张深红背景的照片立刻穿帮：整个背景被判成暗部、文字铺满四周，主体反而被挖空 —— 和「人物从留白中浮现」正好相反。

真正的规则不是「暗」，而是**「偏离背景」**。做法是先测背景亮度 —— 取全图亮度直方图的**众数**，因为背景通常是画面里占地最大也最平的一块（用均值会被主体拉偏）—— 再按各点与它的偏离程度布字。这样亮底暗主体、暗底亮主体两种构图都成立，不需要用户手动切换。

轮廓梯度那一项本来就与明暗极性无关，所以不用改。

### 默认示例图为什么是 data URI 而不是 .jpg

浏览器在 `file://` 下会把同目录的图片视为跨源，画进 canvas 后 `getImageData` 和 `toDataURL` 全部抛错。这个工具两者都用（前者用来判断文字该放哪，后者用来导出），所以双击打开时整个工具会直接失效 —— 恰好破坏了「零依赖、双击即开」这一条。data URI 不受同源策略约束，本地和线上表现一致。

代价是图片要以 base64 存进 js 文件（约 84KB）。换成自己的照片不必改代码，界面里拖进去就行。

### 参数取舍

- `cling`（主体密度）是最值得调的一个。原图的背景文字明显比人物上稀疏得多，密度对比本身就是构图的一部分。调到 0.8 以上背景会干净很多。
- `defocus` 默认 0.35，也就是三分之一的字是虚的。全实会立刻变成"贴上去的"。
- 彩色模式下文字先提饱和度再向白/黑推，否则推完颜色就没了。
